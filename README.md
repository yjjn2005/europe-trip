# 여행 일정 앱 템플릿

이 저장소는 특정 여행(2027년 서유럽·지중해 2개월) 전용이 아니라, **다른 나라·다른 일정으로도 그대로 재사용 가능한 템플릿**입니다.
화면 로직(`app.js`, `style.css`, `index.html`, `worker.js`)과 실제 여행 내용(`data.js`)이 완전히 분리되어 있어,
**새 여행을 만들 때는 `data.js` 한 파일만 새로 채우면 됩니다.**

## 재사용 방법 (새 여행 만들기)

1. 이 저장소를 새 이름으로 복사합니다 (예: `japan-trip`, `q2-2028-thailand` 등).
2. `data.js`를 열어 아래 항목을 새 여행 내용으로 교체합니다. **다른 파일은 건드릴 필요가 없습니다.**

   | 항목 | 설명 |
   |---|---|
   | `TRIP` | 제목, 기간, 인원 등 기본 정보. **`id` 값은 반드시 새 값으로 변경**(동기화 키가 여기서 나옵니다 — 안 바꾸면 예전 여행 데이터와 동기화가 섞일 수 있음) |
   | `REGIONS` | 지역/국가별 요약 카드 (도시·박수·날씨·하이라이트·당일투어) |
   | `REGION_TIPS` | 지역별 "꼭 알아야 할 사항" — `REGIONS`의 `region` 이름과 정확히 일치해야 매칭됨 |
   | `STOPS` | 지도에 표시할 도시 목록. `nation` 값이 같으면 "국가 내 이동"(남색 점선), 다르면 "국가 간 이동"(금색 실선)으로 자동 표시됨 |
   | `DAILY` | 일자별 상세 일정 (날짜·도시·숙소·오전/오후/저녁·비고) |
   | `BUDGET_DETAILED` | 카테고리 → 항목 구조의 예산. 소계·총합계는 화면에서 자동 계산(하드코딩 없음) |
   | `CHECKLIST` | 준비사항 체크리스트 |
   | `ADDRESSES` | 도시별 우버/택시용 주소록 |

3. `config.js`에서 `SYNC_API_BASE`를 새 Cloudflare Worker 주소로 바꿉니다(같은 Worker를 여러 여행이 공유해도 되지만, `TRIP.id`가 다르면 동기화 데이터는 자동으로 분리되어 저장됩니다 — 원하면 Worker도 새로 만들어도 됩니다).
4. `manifest.json`의 `name`/`short_name`도 새 여행 이름으로 바꿔주면 홈 화면 아이콘 이름이 맞게 표시됩니다.
5. GitHub 저장소를 새로 만들고 Pages를 켠 뒤, 동일한 방식으로 Cloudflare Worker(`worker.js`, KV 바인딩 `TRIP_SYNC`)를 배포하면 끝입니다.

## 구조

```
index.html    화면 뼈대 (탭 6개: 개요/지도/일정/예산/체크/주소) — 보통 수정 불필요
style.css     디자인 시스템 (네이비·골드·아이보리) — 보통 수정 불필요
app.js        렌더링·지도·동기화 로직 — 보통 수정 불필요
data.js       ★ 실제 여행 내용 — 새 여행마다 이 파일만 교체
config.js     Google Maps 키 + Worker 주소
worker.js     Cloudflare Worker (기기 간 동기화 서버)
manifest.json / sw.js   PWA(홈 화면 설치, 오프라인 캐시)
```

## 지도 색상 규칙

`STOPS` 배열의 각 도시에 `nation` 값을 넣으면 `app.js`가 자동으로 구간을 계산합니다.
연속된 두 도시의 `nation`이 같으면 **국가 내 이동**(남색 점선), 다르면 **국가 간 이동**(금색 실선)으로 그려집니다.
새 여행이 국내 여행이라면 `nation`을 지역명(예: 제주도/부산)으로 바꿔 같은 원리를 적용할 수 있습니다.

## 예산 구조

`BUDGET_DETAILED`는 `{ category, items: [{ label, note, amount }] }` 배열입니다.
카테고리·항목 개수는 자유롭게 늘리거나 줄일 수 있고, 화면의 카테고리 소계·총합계·1인당 금액은 모두 `app.js`가 그때그때 계산합니다 — 숫자를 화면 쪽에 따로 적어둘 필요가 없습니다.
